What is Node.js?

Run JavaScript everywhere.

A free, open source, cross-platform JavaScript runtime for servers, web apps, command line tools, and scripts.

Same story as the nodejs.org homepage. Point out node:http, the node: prefix, and that this is all core: no dependencies.

Contributing to Node.js

No contribution is too small and all contributions are valued.

CONTRIBUTING.md
  • Code, docs, answers, infrastructure, and advocacy all count.
  • Not a Collaborator yet? Keep at most 10 pull requests open.

github.com/nodejs/node/blob/main/CONTRIBUTING.md

Open governance: people who make significant, valuable contributions become Collaborators with commit access (GOVERNANCE.md). The Developer's Certificate of Origin is why every commit needs a Signed-off-by line: git commit -s.

AI use in Node.js

github.com/nodejs/node/blob/main/doc/contributing/ai-guidelines.md

Decision making should always be based on human judgement instead of machine automation, regardless of whether the automation is powered by AI.

Okay

  • Read and understand the project
  • Treat AI output as a hypothesis, then verify it
  • Disclose AI use and how you checked it
  • Grammar checks and translation

Not okay

  • Pull requests opened by automated tooling
  • AI fixes for "good first issue" issues
  • Automated replies to review feedback
  • Pasting messages generated entirely by AI
The policy changed since RenderATL: AI-automated fixes for good first issues are now explicitly prohibited. Those issues exist to teach new humans. You must be able to explain every change; disclosure is not a disclaimer.

AI policy overview

Use AI to learn faster. Do not use it to bypass human accountability.

Appropriate

  • Explain unfamiliar code
  • Draft a test plan
  • Check wording
  • Suggest debugging paths

Inappropriate

  • Unattended bots
  • PRs you cannot explain
  • Fake repro steps
  • Large opaque rewrites

Human in the loop. Human signs off. Human responsible.

How to sustainably source ideas

Good contributors learn where problems come from, not just where labels appear.

  1. Good first issues Start with curated entry points, like we are doing today.
  2. Recent PRs Learn from recently accepted work.
  3. Docs confusion Fix where your own understanding got stuck.
  4. Test gaps Protect behavior that already exists.
  5. Issue triage Reproduce, reduce, clarify, label.

Make the smallest useful change that you can explain.

Prerequisite recap

You are ready when you can build Node.js and run one test.

  1. A GitHub account with two-factor authentication
  2. Git configured with the same email as your GitHub account
  3. Fork nodejs/node, clone it, and add upstream
  4. The Node.js dev container (recommended) or a local build
  5. tools/test.py test/parallel/test-assert.js passes

Before you open the PR

Make the reviewer's job easier. That is part of being helpful.

  • Clear title
  • Tests or docs updated
  • Small scope
  • Signed-off commit
  • Why this matters
  • Respectful follow-up
